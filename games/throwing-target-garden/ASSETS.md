# Throwing Target Garden — asset log and production plan

The production rebuild uses one child-facing material language: **Paper Garden,
cozy felt fabric variant**. Every visible target, beanbag, card, carrier,
diagram, mascot flower, and reward is authored raster art. Runtime HTML text
sits on raster felt carriers; DOM/canvas supplies layout, hit areas, motion, and
particles only.

The complete behavior and art inventory are canonical in `game-design.md`.
This file records source and processing as each item crosses the production
gate. Production rows record installed runtime output and independent critic
results.

### Krea 2 → GPT Image 2 visual-development pass

The production handoff now also preserves the explicitly requested sequential
style pass. Four **Krea 2** studies were generated first through the approved
LAN `krea2-turbo-t2i` workflow at 1024×768, using the same felt-material brief
and seed 42. Exact prompts, hashes, dimensions, dates, and licenses live beside
each source in `assets/source/krea2-concepts/*.recipe.json`:

- `01-world-stage.png` — open felt garden framing and canopy language;
- `02-core-play.png` — target, basket, numeral, and beanbag material language;
- `03-mode-shelf.png` — coordinated target/color/sequence activity cards;
- `04-garden-match.png` — basket-first reward, flowers, target, and confetti.

`concept-contact.webp` is the deterministic 2×2 review sheet. Two earlier Krea
safety-diagram attempts are retained with `rejected` recipes: seed 42 placed the
tablet stand inside/overlapping the basket, and seed 1337 still made the objects
touch while omitting the readable landing arc. Neither is a runtime, reference,
marketing, or install candidate.

The four accepted Krea studies then became **style references** for the built-in
GPT Image 2 `krea-synthesis-safe-setup.png` pass. Its exact prompt, four
hash-bound inputs, output hash/dimensions, and visual disposition are in
`krea-synthesis-safe-setup.recipe.json`. It cleanly separates the secured tablet
from the landing basket and keeps the beanbag trajectory away from the device.
It remains a visual-development reference because the installed
`assets/ui/setup-safe.webp` already has deterministic transparency, responsive
layout coverage, and browser QA; replacing a validated runtime asset merely to
prove model chronology would reduce evidence rather than improve the game.

Transparent sources use a perfectly flat key color absent from the subject.

source masters. `assets/qa/contact-magenta.webp`, `contact-green.webp`, and
`assets/qa/report.json` record the final alpha/dimension audit.

## Voice inventory and QA

`assets/audio/lines.json` contains 49 authored lines from `game-design.md`.
After explicit authorization, all 49 were produced through
`qwen3-tts-voiceclone`, Whisper-transcribed, text-hash/checksum bound, and
published atomically in `manifest.json`: 48 accepted seed 7 and one accepted
seed 8, with transcript ratio 1.0 and durations from 0.878 to 10.3 seconds.
`assets/audio/qa.json` records the exact intended/heard text, seed, duration,
bytes, SHA-256, and source-text hash for every clip. The 185-check real-Chrome
run fetches and hashes every local clip, proves recorded welcome playback, then
forces `{}` as the manifest and proves the exact Web Speech fallback. Runtime
audio makes no remote requests.

## Source-prompt provenance limitation

The built-in GPT Image 2 masters contain provider/C2PA generation provenance,
but neither the files nor the accessible session artifacts expose the original
verbatim prompts or deterministic seeds. The source masters, exact crop map,
processing code, visible-content requirements, creator, and CC BY 4.0 license
are committed; this log does **not** invent missing prompts or seeds. New LAN
assets use canonical templates and commit their complete prompt, workflow,
dimensions, seed, processing, and candidate/install status in recipe JSON.
